# Dex 0.6.7

Typing into a pane no longer goes through the database. Until now every single character did.

**Download:**
- **Windows:** `Dex_0.6.7_x64_en-US.msi` below. Windows 10 1809+ or Windows 11, with Claude Code and Git for Windows installed. Not code-signed yet, so SmartScreen will say *Windows protected your PC*; click **More info → Run anyway**. Installing over an earlier version upgrades it, and your workspaces, hooks and settings are kept.
- **macOS:** `Dex_0.6.7_macos_apple-silicon.dmg` for an M-series Mac, `Dex_0.6.7_macos_intel.dmg` for an Intel one. macOS 11 or later. The first launch needs **Open Anyway**, as before.

All three appear a few minutes after the release, once GitHub has built them.

## Fixed

- **Typing into a pane no longer touches the database** (issue #86). It did on every character. `pane.send` resolved its target by reading **every** pane row through Dex's single connection — so each keystroke queued behind every hook from every agent (five agents hook at each prompt and each tool batch) and every query the watchdog makes. A pane would take no input for a minute and then take all of it at once, while output kept arriving, which is what "it froze" looked like. A keystroke arrives with its own pane's id and Dex already knows whether that pane is live, so it now writes straight to it; the lookup stays for what it is for — a label, a `--pane` argument from an agent, an ambiguous name.
  - **This does not make a starved machine fast.** If your WSL distro is paging, everything in it is slow and Dex cannot help that. It is a round trip that should never have been in front of a keystroke.
- **The watchdog no longer writes down "something is running under its shell" when it could not tell** (issue #88). A silent agent whose shell was not in the process table, or whose distro never answered, was logged as being inside a long tool call — with `under=None` printed beside it, so the line contradicted itself. No agent was ever ended on that: the decision has always needed real evidence. Only the log was wrong, and the log is the first place to look when a pane has gone quiet.

## Changed

- **The process table is read once per watchdog sweep instead of twice** (issue #86). Reading it is a PowerShell start and an enumeration of every process — 620 ms for 370 processes on the machine this was measured on — and a sweep asked for it twice over: once for whose Claude Code has gone, once for whether a quiet agent is inside a tool call. The two now share one read, with a one-second limit on how stale an answer either will take, which keeps the two-look confirmation that decides an agent has gone honestly two looks.

## Added

- **Dex notes anything that took too long, with the duration** (issue #86). A keystroke that waited more than half a second to reach a shell, or a watchdog sweep that overran five of its fifteen seconds, gets a line in `dex.log`. The log arrived in 0.6.6; this is what makes it answer *what* took the time, so a pane that felt frozen leaves a record instead of an argument.
