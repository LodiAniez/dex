# Dex 0.6.6

Dex now says when an agent has gone quiet, takes away the worktrees nobody is working in, and writes a log you can read when something goes wrong.

**Download:**
- **Windows:** `Dex_0.6.6_x64_en-US.msi` below. Windows 10 1809+ or Windows 11, with Claude Code and Git for Windows installed. Not code-signed yet, so SmartScreen will say *Windows protected your PC*; click **More info → Run anyway**. Installing over an earlier version upgrades it, and your workspaces, hooks and settings are kept.
- **macOS:** `Dex_0.6.6_macos_apple-silicon.dmg` for an M-series Mac, `Dex_0.6.6_macos_intel.dmg` for an Intel one. macOS 11 or later. The first launch needs **Open Anyway**, as before.

All three appear a few minutes after the release, once GitHub has built them.

## Added

- **An agent that has gone quiet says so** (issue #67). A `running` agent whose last hook is older than `[agents] quiet_after_seconds` — five minutes by default — shows **nothing for 12m** beside its status, in the pane header, in the office panel and in `dex agent list`. Hooks arrive at every tool call, so one long silence is one long command: a build, a test suite, or one that will never come back. They look identical from outside, so Dex only says it; what to do about it is yours.
  - This is the line that tells you a still office is a busy agent rather than a dead one. Four agents each starting a five-minute test suite go silent together, and before this there was nothing to distinguish that from four agents having died.
- **`dex worktree prune <repo>`** clears out the worktrees nobody is working in (issue #70). One goes only when no pane has a shell running in it, its tree is clean (untracked files count), and its branch has nothing the main checkout's branch has not. Everything else stays, each with the reason it stayed, and `--dry-run` says what would go first.
  - `dex worktree list <repo> --sizes` measures what each one is holding.
  - **Those sizes are what the files add up to, not what the disk gives back.** pnpm and its like hardlink one copy of a package file into every `node_modules` that wants it, so the same bytes are counted in each place they appear: thirty worktrees of one monorepo measured 157 GB, and deleting all thirty returned 4.3 GB.
  - Ignored files go with the folder, exactly as they do for `git worktree remove` — installed dependencies, build output, and a hand-written `.env` that lives only there. Dry-run first.
- **Worktrees that clear themselves**, if you turn it on: `prune_merged_worktrees = true` under `[agents]` (issue #74). Hourly, and more careful than the prune you run by hand: a worktree goes only when nothing is running in it, its tree is clean, nothing has worked in it for `prune_after_hours` (a day by default), **and the remote no longer has its branch**.
  - That last one matters. Merging a pull request with a squash writes a new commit, so the branch is never an ancestor of `main` afterwards and the local "is it merged" test says no for ever. Dex asks your remote whether the branch is still there, which is true however you merge.
  - A branch no remote ever had is never taken — that folder may hold the only copy of its work — and neither is one with commits you have not pushed.
  - Every removal is written to the workspace's activity log, and to `.dex/activity.log`, so a worktree never simply vanishes. `dex worktree prune <repo> --auto --dry-run` runs the identical pass and takes nothing, so you can watch it before trusting it.
  - **Off by default**, deliberately: not pruning costs disk, pruning wrongly costs an afternoon.
- **A log you can read** (issue #73). Dex writes what it is doing to `%APPDATA%\Dex\dex.log` (`~/Library/Application Support/Dex/dex.log` on macOS), 8 MB with one `dex.log.1` kept behind it. It went to stdout before, which a windowed app does not have, so every warning the daemon wrote was discarded. This is the first place to look when something goes wrong, and the first thing to attach to an issue. `RUST_LOG=trace` turns it up for a session.
- **`dex repo forget <repo>`** drops a repository's registration (issue #72), for one whose folder you have moved or deleted.

## Changed

- **A distro that stops answering is left alone for a while** — 30 seconds, then a minute, up to five — instead of being asked again every sweep (issue #73). One probe waits up to 15 seconds and the watchdog sweeps every 15, so a wedged distro used to have the sweep's whole attention, and everything behind it in that sweep waited too, including waking the agents with messages waiting. The window now says which distro went quiet: a still office is not the same as a lost agent.
- **A registered repository whose folder has gone says so** (issue #72). `dex repo list` shows it as `(gone)` rather than `(detached)`, `dex doctor` fails a **repos** check naming it, and any command that needs git in it says the registration is the stale part — and lists the worktrees Dex made from it, which are now orphaned. Those are left on disk on purpose: git in them points at a repository that no longer exists, so nothing can tell you what is committed in them or even show you a diff, which makes keeping or deleting them a judgement only you can make.
- **Nothing on a sleeping WSL distro is touched** (issue #77). Reading a folder through `\\wsl.localhost` starts that distro, so the hourly prune never looks at one that is not running — Dex will not wake a VM to decide whether to delete something.
- **A subagent's hooks keep its parent from looking quiet.** A parent inside one long `Task` call is working, not silent.

## Fixed

- A quiet agent's line appeared only when something else happened to change in the database, so in the case it was written for — an agent stuck inside one tool call — it would never have appeared at all.
- `quiet_after_seconds` is held between a minute and a day: large enough values turned the threshold negative, which made every agent quiet for ever.
