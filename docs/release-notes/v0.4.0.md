# Dex 0.4.0

Panes that go where you want them: spawned agents line up instead of slicing their lead, any pane can be dragged to a new place, and any pane can be popped out into a window of its own.

**Download:** `Dex_0.4.0_x64_en-US.msi` below. Windows 10 1809+ or Windows 11, with Claude Code and Git for Windows installed. Not code-signed yet — SmartScreen will say *Windows protected your PC*; click **More info → Run anyway**. Installing over an earlier version upgrades it; your workspaces, hooks and settings are kept.

## New

### Spawned agents line up beside their lead

Every spawn used to split the pane it came from, so a lead that spawned six agents was sliced six times and the six landed wherever the splits put them. Now:

- **The first agent** splits the lead's pane the way it asked (to the right by default, or `--direction down`).
- **Every later one** goes beside the newest of its siblings, the other way — so the agents form a strip beside the lead (or a row below it), and **the lead keeps its half**.
- **A workspace you have arranged** as *main-left*, *main-top* or *tiled* (`Ctrl+Shift+Space`) **stays arranged** as agents arrive: a grid grows by one and nothing else moves. A layout you set by hand — a divider you dragged — is left exactly as it is, and the new agent joins the strip.
- Your own hires, from HR or `dex agent spawn`, line up the same way, and never split an agent you started yourself by typing `claude`.

### Drag a pane to move it

Grab a pane by its header and drop it on another:

- **on an edge** — it sits beside that pane on that side, taking half its space; the gap it left closes up;
- **in the middle** — the two trade places.

A highlight shows where it will land. **Escape**, or letting go anywhere else — even outside the window — puts it back, and Escape during a drag never reaches the terminal (where it would interrupt an agent). A plain click on a header still just focuses the pane. `Alt+Shift+Arrow` still moves a pane a step at a time from the keyboard.

### Pop a pane out into its own window

**↗** in a pane's header opens it in a **separate window**: put it on another monitor, resize it, leave it behind Dex. The terminal moves with its **scrollback and whatever is running in it** — an agent keeps working — and the main window closes up round the gap.

- **Dock ↩** in that window, or the window's own close button, puts the pane back **exactly where it was**, with everything that happened while it was out, at its own width again.
- **Go to pane** (from the office or a toast) brings its window forward.
- The main window's focus moves off a pane that goes out, so a shortcut like `Ctrl+Shift+W` never reaches it unseen.
- **Closing Dex's main window** closes its pop-outs too. The last pane in the main window stays in it.
- If a pop-out window vanishes without docking, its pane still comes home.

## Known limitations

- In the office, *their screen* for a popped-out pane shows what it had when it left; the main window no longer receives its output.
- Pop-outs are not remembered across a restart: every pane opens in the main window.
- If a pop-out window takes more than five seconds to open while its pane is pouring out output, some of that output can be dropped, marked as dropped output always is.
- Windows only, no WSL agents yet, scrollback does not survive a restart, diff and markdown panes poll, unsigned installer. Tested against Claude Code 2.1.274.
