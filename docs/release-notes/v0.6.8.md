# Dex 0.6.8

Two things that only went wrong while several agents were working: the process table that tells Dex who is still alive, and the message that wakes an agent.

**Download:**
- **Windows:** `Dex_0.6.8_x64_en-US.msi` below. Windows 10 1809+ or Windows 11, with Claude Code and Git for Windows installed. Not code-signed yet, so SmartScreen will say *Windows protected your PC*; click **More info → Run anyway**. Installing over an earlier version upgrades it, and your workspaces, hooks and settings are kept.
- **macOS:** `Dex_0.6.8_macos_apple-silicon.dmg` for an M-series Mac, `Dex_0.6.8_macos_intel.dmg` for an Intel one. macOS 11 or later. The first launch needs **Open Anyway**, as before.

All three appear a few minutes after the release, once GitHub has built them.

## Fixed

- **A bullet in anyone's command line no longer loses the whole process table** (issue #91). Dex reads the process table by asking PowerShell for it as JSON, and PowerShell writes its output in the console's code page — which, for a windowed app, is the system OEM one rather than UTF-8. A character that code page has no room for was not dropped or replaced: it was mapped onto the nearest byte, and the nearest byte to `•` is a control character that makes the JSON unreadable. One process anywhere on the machine with a bullet, an arrow or a curly quote on its command line, and **no** process table came back at all. Agents are what put those characters on command lines, in commit messages and PR bodies, so it got worse the more of them were running: 186 failures in ten days on the machine this was found on, 77 of them on one day with three agents in worktrees. The script now says what encoding to print in, and a damaged character costs the command line it is in rather than every process on the machine.
  - **What that cost while it was broken:** the watchdog could not confirm that anybody had gone, so an agent you quit or that crashed stayed `running` for ever and kept its seat against the concurrency limit; the terminal-choice dialog called every pane busy; and `dex agent prompt` fell back to trusting the agent's last known status, which is how a message can be typed into a shell that no longer has Claude Code in it.
- **An agent's nudge is no longer left sitting in the prompt box unsent** (issue #94). When one agent messages another, the recipient is woken by typing a line into its pane and pressing Enter. The Enter is sent as its own write, because Claude Code reads text and Enter arriving together as a paste and turns the Enter into a newline instead of submitting — but it was sent after a fixed 50 ms, and two writes only arrive separately if the pane read the first one in between. The nudge arrives exactly when the recipient has finished a turn and has its transcript to write and its hooks to run, which can easily take longer than that; then both writes arrive together, and the line sits in the prompt box until somebody presses Enter by hand. The agent was never woken, and because the wake had already been recorded, no later sweep tried again. Enter now waits for the pane to show that it took the text — a terminal draws what is typed into it, and that cannot happen without having read it — with the old 50 ms as the floor and a cap so that a pane which says nothing still gets its Enter.
  - This also covers `dex agent prompt` and `dex agent stop`, which type into a pane the same way. Your own keystrokes never went through that path.
