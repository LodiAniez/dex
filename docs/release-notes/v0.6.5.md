# Dex 0.6.5

An agent's worktree now lives inside the workspace it is for, and one pane that stops reading its input no longer holds up the others (issue #63).

**Download:**
- **Windows:** `Dex_0.6.5_x64_en-US.msi` below. Windows 10 1809+ or Windows 11, with Claude Code and Git for Windows installed. Not code-signed yet, so SmartScreen will say *Windows protected your PC*; click **More info → Run anyway**. Installing over an earlier version upgrades it, and your workspaces, hooks and settings are kept.
- **macOS:** `Dex_0.6.5_macos_apple-silicon.dmg` for an M-series Mac, `Dex_0.6.5_macos_intel.dmg` for an Intel one. macOS 11 or later. The first launch needs **Open Anyway**, as before.

All three appear a few minutes after the release, once GitHub has built them.

## Changed

- **An agent's worktree goes inside its workspace:** `<workspace root>\.dex\worktrees\<repo>\<branch>`, beside the context mirror, instead of `%USERPROFILE%\dex\worktrees`. A checkout belongs with the work it is part of. A workspace you made without naming a root is rooted at your home folder, so there that means `%USERPROFILE%\.dex\worktrees`.
  - Worktrees you already have stay where they are, and `dex worktree remove` still finds them by branch. Nothing is moved.
  - `worktree_base` in `config.toml` is now for a worktree with nowhere else to go: no workspace at all (`dex worktree add` without `--workspace`), a root on the distro's side of `\\wsl.localhost` that Windows git cannot work in, or a root whose folder or repository will not take one.
  - A workspace's root is usually the repository itself, so the worktree usually sits inside a checkout of that repository. Dex tells git to look away twice — a `.gitignore` in `.dex\worktrees`, and a `**/.dex/` line in that repository's `.git\info\exclude`, which `git clean` cannot delete — so nothing Dex keeps in a workspace shows in its `git status` or is taken into a `git add -A` as an embedded repository. That also stops the context mirror showing there, which it did before.
  - **Two things to know about worktrees inside a repository,** and a `README.txt` in the folder repeats the first: `git clean -ffdx` in that checkout **deletes every worktree under it, uncommitted work and all** — no ignore and no `git worktree lock` stops a second `-f` — and anything that looks up the folder tree sees the project around the worktree, so Claude Code reads every `CLAUDE.md` above it (possibly a different branch's), Node resolves modules upwards, Cargo walks up to a `[workspace]`, and ESLint reads its configs.
- **`dex worktree remove` finds a worktree wherever it was made**, including after its agent has switched branch or started a rebase. A removal that fails part-way — on Windows, usually a file something still has open — leaves git no longer tracking the worktree while its folder stays; Dex now names that folder to check and delete, rather than saying there is no such worktree.
- **`dex repo scan` skips `.dex`,** so scanning a workspace no longer registers its agents' worktrees as repositories.

## Fixed

- **One pane that stopped reading its input could freeze every pane** (issue #63). All panes shared a single lock, and typing into a pane held it for the whole write — ConPTY takes about a second per megabyte, and a pty whose child has stopped reading blocks outright. While that ran, nothing else could type into another pane, resize, open or close one, and the watchdog could not read what it needs to notice an agent that has gone quiet.
  - Each pane's writer now has a lock of its own, so a slow or stuck write holds up only its own pane.

## Known limitations

- A worktree inside the repository it came from is deleted by `git clean -ffdx` in that repository, as above.
- Waking an agent types into its pane wherever your cursor is: a half-written line there is submitted with the nudge. Digests are not typed, so they never interleave.
- An agent Dex has lost track of (`unknown`) is woken too, since a dropped `Stop` hook looks exactly like an agent that finished quietly. Dex checks first that Claude Code is still running in the pane, but only where the process table can be read; in a WSL pane whose distro does not answer, a nudge can still be typed into a bare shell, which runs it as a command.
- A second worktree of one repository in one workspace replaces the first's record; removal still finds it by branch unless it has also left its branch.
- An agent spawned without a repo in a workspace whose root is your Windows home folder, and running in WSL, logs a harmless failing hook. Claude Code reads the home folder's settings as project settings there. Use a workspace root other than the home folder to avoid it.
- A pane is either PowerShell or the chosen distro, one distro at a time.
- **macOS:** privacy prompts can name Dex (**Don't Allow** is safe); clicking a notification opens Script Editor (#40); the Intel build hasn't been run on an Intel Mac.
- Scrollback doesn't survive a restart, diff and markdown panes poll, and the installers are unsigned.

## Verification

In CI: 529 Rust tests on Windows and 478 frontend tests; macOS runs the same suite without the Windows-only platform tests. Both changes were written test-first, and each behaviour was checked by breaking it on purpose and watching a test fail — including the git behaviour itself: a test cleans a checkout with `git clean -fdx` and reads `git status` afterwards.

Each went through production-level review: one round for the pane writer, four for the worktrees. Those rounds found, among others, a write that could freeze the app while it held the pane map, a removal that reported success while leaving the worktree on disk, and an `info/exclude` line anchored so that it protected nothing for a workspace rooted below a repository's top — all fixed before merge.

Tested with simulated Claude Code hooks and real shells, following Claude Code's documented events. The message waking has still not been watched against a live Claude Code session.
