# Dex 0.6.3

Spawned agents always get their whole brief and know who they are, and an agent keeps its identity through `/clear` and `/resume` (issue #55).

**Download:**
- **Windows:** `Dex_0.6.3_x64_en-US.msi` below. Windows 10 1809+ or Windows 11, with Claude Code and Git for Windows installed. Not code-signed yet, so SmartScreen will say *Windows protected your PC*; click **More info → Run anyway**. Installing over an earlier version upgrades it, and your workspaces, hooks and settings are kept.
- **macOS:** `Dex_0.6.3_macos_apple-silicon.dmg` for an M-series Mac, `Dex_0.6.3_macos_intel.dmg` for an Intel one. macOS 11 or later. The first launch needs **Open Anyway**, as before.

All three appear a few minutes after the release, once GitHub has built them.

## Fixed

- **A spawned agent sometimes started without its task.** The startup context stopped at the first line that didn't fit its budget, so a brief longer than about 2,000 characters was dropped along with everything after it. The agent was told to "begin the task described in your workspace context" with no task in it.
  - Now the brief is always given whole, and the rest of the startup context fits around it.
  - Claude Code shows an agent at most 10,000 characters at startup, so `dex agent spawn` refuses a brief over 8,000 characters. The error tells the lead to put the detail in shared context and name the key.
- **An agent got a new id after `/clear`.** Claude Code ends the session and starts a new one on `/clear`, and Dex treated that as a new agent. The agent's children, messages and `dex agent stop` then pointed at an id that no longer existed.
  - The agent now keeps its id through `/clear` and compaction.
  - `/resume` goes to the right agent: the resumed conversation's own agent if the pane had one, otherwise the same agent carrying on.
  - Starting `claude` again after quitting is still a new agent, and a new Claude Code never takes over an old agent's identity.

## Changed

- **Agents are told who they are:** their label and id, so they can find their own row in `agents_list`.
- **The repo line in the startup context says where the repo is checked out:** `Repo api is on feat/x, checked out at <path>`. A workspace's worktree can be on a different branch from the repo's own checkout, and the old line didn't say which it meant.
- **Other agents' briefs in the list of agents are shortened to one line,** so one long brief can't crowd everything else out.

## Known limitations

- An agent spawned without a repo in a workspace whose root is your Windows home folder, and running in WSL, logs a harmless failing hook. Claude Code reads the home folder's settings as project settings there. Use a workspace root other than the home folder to avoid it.
- A pane is either PowerShell or the chosen distro, one distro at a time.
- **macOS:** privacy prompts can name Dex (**Don't Allow** is safe); clicking a notification opens Script Editor (#40); the Intel build hasn't been run on an Intel Mac.
- Scrollback doesn't survive a restart, diff and markdown panes poll, and the installers are unsigned.

## Verification

In CI: 479 Rust tests on Windows, 478 on macOS, and 478 frontend tests, including new ones for every fix above, each written first and seen failing. The fix went through five rounds of production-level review, and every blocker and should-fix was fixed.

It was tested with simulated Claude Code hooks, following Claude Code's documented events. It hasn't been run against a live Claude Code session yet.
