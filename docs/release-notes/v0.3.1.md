# Dex 0.3.1

An agent that asks you something now says so — everywhere Dex shows a status, and in a speech bubble in the office.

**Download:** `Dex_0.3.1_x64_en-US.msi` below. Windows 10 1809+ or Windows 11, with Claude Code and Git for Windows installed. Not code-signed yet — SmartScreen will say *Windows protected your PC*; click **More info → Run anyway**. Installing over an earlier version upgrades it; your workspaces, hooks and settings are kept.

**After upgrading, run `dex skill install` once** (or press *Install skill* in the setup panel). The skill agents read gained a section in this release.

## Fixed

### An agent waiting on your answer looked idle

An agent told to check before overwriting a file ended its turn with *"Reply "yes" and I'll overwrite the file…"*. That is not a permission dialog: to Claude Code the turn was over, so Dex showed the agent **idle** — and since 0.3.0 an idle agent in the office goes for a coffee. It sat unanswered, twice, while its lead sent it reminders.

Now an agent that asks you something shows as **needs you**: in its pane header, the sidebar dot, the title-bar count, a toast that says what it asked, its panel, and the office — hand up, the question in a **speech bubble at its mouth**, and it stays at its desk.

Dex hears a question in two ways.

**For certain: Claude Code's question dialog.** When an agent asks with the `AskUserQuestion` tool, a hook fires, and Dex shows it the moment it asks. It used to read *permission to AskUserQuestion*, then, a few seconds later, *Claude needs your permission*; now it is the question itself, and the notification that follows a dialog no longer replaces what the dialog said. You answer a dialog in the agent's pane. Agents are told this is how you hear them: one line in the context every session starts with — stated as a fact, because that context orients and does not instruct — and a section in the `dex-agentic` skill. In testing, an agent given a decision that was the owner's, with no mention of any tool, chose the dialog.

**As a fallback: how the turn ended.** Agents do not always use the dialog. When a turn ends, Claude Code hands Dex the closing message, and Dex reads how it ends: the last two sentences or list items ask if they end in a question mark, use a phrase such as *reply "yes"*, *say the word*, *tell me when* or *it's your call* (as whole words), or are simply built as a question — *"what would it be."*, *"Would you like the long version."* — whatever they end with. Closing pleasantries (*"let me know if you need anything else"*) are not questions, and nor are offers that block nothing (*"I can delete them if you want"*). The agent stays promptable — answering is just a prompt — and the next prompt clears it.

It is a guess about prose, so it has a net under it: **what any idle agent said last is shown** in a quiet line under its desk and in its panel, so a missed question is visible rather than silent. Run over 247 real closing messages from Claude Code transcripts, it flagged 81; the ones found by hand to be missing were added, each as a test.

Also: **Announce** warns when it would reach an agent in the middle of a question of its own, since it arrives as their next prompt and may be taken for the answer. Other agents are told neither what a colleague asked you nor what it said; `dex agent list` shows `idle (asked you: …)` for an asker and plain `idle` for one that merely finished.

### "label "lead" is already used" — with no agent in sight

Labels belong to panes, and a pane you opened outlives its agent and keeps its label. The office shows agents, so nothing visible held the name, and the refusal read as a bug. **Hire an agent** now checks as you type: it says what holds the label — an agent's pane, or a pane still open in Terminal view with no agent in it — and offers the next free one (*Use "lead-2"*) in a click. It also says when a label has a space in it or is longer than 32 characters, and never offers one the daemon would refuse. The CLI's and agents' error says why as well.

## Known limitations

Windows only, no WSL agents yet, scrollback does not survive a restart, diff and markdown panes poll, unsigned installer. Noticing a question in prose is a guess: one phrased with no cue, no question mark and no question's grammar in its last two sentences is missed (the agent shows idle, with its closing words under its desk), and a finished turn that happens to end like a question — *"Should you want to revert, run…"* — shows as needing you until the next prompt. What an agent said last is shown as written. The session-context line needs a Claude Code whose `Stop` hook carries the closing message and which has the `AskUserQuestion` tool; tested against 2.1.274.

## Verification

368 Rust tests and 390 frontend tests, each rule written as a failing test first; four rounds of review with their findings fixed. With real Claude Code sessions in an isolated window: an agent told to end its question with a period (*"Which project should I prioritize first today."*) showed as needing you at once, was answered from its panel, finished, and its closing words appeared under its desk; an agent given a decision that was the owner's used the question dialog unprompted, and Dex showed the question itself, still there after the follow-up notification. The hire form was driven through a taken label, an agent's label, a free one, and the offered one — without hiring.
