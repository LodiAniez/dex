# Dex 0.2.0

Three ways of looking at a workspace: the terminals, your agents as cards, and your agents in an office.

**Download:** `Dex_0.2.0_x64_en-US.msi` below. Windows 10 1809+ or Windows 11, with Claude Code and Git for Windows installed. Not code-signed yet — SmartScreen will say *Windows protected your PC*; click **More info → Run anyway**. Installing over an earlier version upgrades it; your workspaces, hooks and settings are kept.

**After upgrading, run `dex skill install` once** (or press *Install skill* in the setup panel, which will offer itself). The skill agents read changed in this release.

## New

### Terminal · Cards · Office

A switch in the title bar — also *Terminal view*, *Cards view*, *Office view* and *Next view* in the palette. Cards and Office take over the whole workspace area; your panes keep running underneath, and Terminal brings them back exactly as they were. Dex remembers the view you chose; `[ui] view` in `config.toml` sets what a workspace opens as before you have chosen.

Every agent is a person: a name and a look worked out from its id, so they are the same after a restart, with the label you gave its pane as its role. An agent that has spawned others is the **lead**. Names are for reading — agents still message each other by label, which the office always shows beside the name.

**Cards.** A card is that agent's screen: its terminal, live, under its name, status and brief. On the card itself: a box to **prompt** it (Enter sends, Shift+Enter is a new line), **Go to pane**, **Details** and **Clock out**. **Expand** opens its output large in a popup, with the history behind the visible screen, following the newest line unless you have scrolled up to read. An agent that needs you says what for across the top of its card — *Waiting for you: permission to Edit …/legacy/client.rs* — and that line takes you to its pane.

**Office.** A floor plan that scales to the window. Someone typing is working; a raised hand and a **?** needs you; a red **!** has stopped; still, with a dim screen, is idle. A spawned agent walks in from HR to its pod. When one agent messages another, the sender gets up and carries it over, and the two are seen talking; a lead briefing three agents makes one round of it, desk to desk. Whoever ends — clocked out, dismissed by its lead, or finished — walks to the exit, turns, waves, and goes. If Windows is set to reduce motion, nobody walks.

**From either view:** *Hire an agent* in HR spawns one exactly as `dex agent spawn` does. *Announce* (the loudspeaker) sends one prompt to every agent, tells you first who will hear it, and skips anyone it cannot safely type at. *Details* shows who an agent reports to, its brief, its screen, and **what it has done** — its own record, newest first: notes, what it stored, who it messaged, who it hired. *Memo* leaves a message in its inbox, which wakes it if it is idle.

### Ending agents

- **Clock out** asks first, then sends `/exit` so the session ends properly — interrupting first if the agent is mid-turn, and falling back to Ctrl+C only if it is still there a few seconds later — and closes its pane. From a terminal: `dex agent stop <label> --graceful --close-pane`.
- **Stopping an agent Dex spawned closes the pane Dex made for it**, so a lead told to dismiss its agents does not leave a row of empty shells. An agent you started by typing `claude` keeps its pane, and a workspace always keeps its last one.
- **An agent may stop only itself and the agents it spawned.** A child told to "stop the others" is refused. You may stop anyone.

### Also

- **Ten agents per workspace** by default (was six); `agents.max_concurrent` still sets it.
- **The activity stream opens as a popup** over whatever view you are in, from the title bar or *Show activity* in the palette. `dex pane create --kind activity` still docks it as a pane.

## Fixed

- **Spawning an agent opened a claude.ai tab** — one per agent. With Claude in Chrome on by default, every new Claude Code session connects to the browser extension. Spawned agents now start with `--no-chrome`; `agents.spawn_chrome = true` leaves the flag out.
- **Pane shells no longer inherit the identity of a Claude Code session Dex was started from**, which made every `claude` in a pane take itself for that session's child and save no transcript.
- **Dex only types at an agent while Claude Code is there to read it.** A pane is Claude Code only while Claude Code runs in it: in the first seconds after a spawn, and after Claude Code has crashed or been quit with Ctrl+C, it is a shell, which runs what is typed into it. Prompts and announcements now go through the daemon, which refuses unless the agent has started, is idle or working, and has a Claude Code process alive in its pane — and ends on the spot an agent it finds gone.
- **"Needs you" says what for**, follows the dialog on screen when an agent asks twice in a row, names a command by what it runs rather than what it carries (`curl -H …`), and is not told to other agents.
- **A pane of a kind this version does not know gets an explanation, never a shell.**

## Known limitations

Windows only, no WSL agents yet, scrollback does not survive a restart, diff and markdown panes poll, unsigned installer. An agent whose Claude Code has gone without saying so is noticed when you try to reach it or its pane exits, not before. The rule about who may stop whom guards against a confused agent; it is not a security boundary. Tested against Claude Code 2.1.274, which has no todo tool — hence *what it has done* rather than a checklist.

## Verification

269 Rust tests and 309 frontend tests, each rule written as a failing test first; three rounds of review with their findings fixed. End to end with real Claude Code sessions: a real lead spawned three agents with a task each; the requirement was then changed by telling only the lead, and all three idle agents woke, read their inbox and rewrote their notes to the new rule within 18 seconds. The views, cards, popup, hire, announce, clock-out and walks were each driven through the real window.
