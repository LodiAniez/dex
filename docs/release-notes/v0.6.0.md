# Dex 0.6.0

On Windows, Dex's panes and agents can run inside WSL. Choose the terminal once, PowerShell or a WSL distro, and every pane and agent opens there.

**Download:**
- **Windows:** `Dex_0.6.0_x64_en-US.msi` below. Windows 10 1809+ or Windows 11, with Claude Code and Git for Windows installed. Not code-signed yet, so SmartScreen will say *Windows protected your PC*; click **More info → Run anyway**. Installing over an earlier version upgrades it, and your workspaces, hooks and settings are kept.
- **macOS:** `Dex_0.6.0_macos_apple-silicon.dmg` for an M-series Mac, `Dex_0.6.0_macos_intel.dmg` for an Intel one. macOS 11 or later, with Claude Code and Git installed. The first launch needs **Open Anyway**, as in 0.5.0.

All three appear a few minutes after the release, once GitHub has built them.

## New

### PowerShell or WSL

With WSL installed, choose where Dex runs: **Terminal** at the top of the setup panel (*Setup checks* in the palette), or `dex pane terminal wsl:Ubuntu` (`dex pane terminal windows` to go back).

- **Everything new opens there:** a new workspace, a split, and every agent spawned, by you or by another agent.
- **Running panes are never moved without asking.** After you choose, the panel lists the panes still in the old terminal. Plain shells come ticked. A pane running anything, or holding an agent, comes unticked, since restarting it ends what runs in it. Only the ticked ones restart in the new terminal, in the same folder, with their scrollback kept. The rest move when Dex next starts.
- **Panes in WSL** show their distro in the header. If the chosen distro is uninstalled, Dex opens in PowerShell and says so.
- **Agents in WSL** are full Dex agents: status, notifications, shared context, messages, spawning, and crash detection. Nothing of Dex runs inside Linux; agents there talk to the Windows app through `dex.exe`.

### Getting a distro ready

Once per distro:

1. Install Claude Code inside it and sign in (`curl -fsSL https://claude.ai/install.sh | bash`, then `claude`).
2. Press **Set up Ubuntu** in the setup panel, or run `dex wsl setup Ubuntu`. This puts a `dex` command in `~/.local/bin` and installs Dex's hooks, MCP server and skill into the distro's Claude Code. `dex wsl status Ubuntu` checks it, including that `dex` really runs there.

Setup finds a Claude Code installed with nvm. It refuses a Linux `~/.claude` that links to your Windows one, and when something is missing it says which step and why.

### Worktrees in WSL

An agent in WSL given a worktree gets one made by the distro's own git with `--relative-paths`, so git on both sides reads it. This needs git 2.48 or later on both sides, which Dex checks first. It also marks the repository's format, so an older git, or a tool built on an older libgit2, refuses the repository afterwards. A pane in a worktree made by Git for Windows stays on Windows.

### Also

- The Windows installer is now built and checked on GitHub, as the Mac images are.

## Known limitations

- A pane is either PowerShell or the chosen distro; there is no per-pane choice, and one distro at a time.
- Setting up a distro needs its Claude Code installed first; the MCP server is registered with the distro's `claude`.
- **macOS:** privacy prompts naming Dex (**Don't Allow** is safe); clicking a notification opens Script Editor (#40); the Intel build has not been run on an Intel Mac.
- Scrollback does not survive a restart, diff and markdown panes poll, and the installers are unsigned.
