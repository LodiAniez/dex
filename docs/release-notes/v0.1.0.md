# Dex 0.1.0

First release. Dex is a Windows terminal workspace for running several Claude Code agents side by side, with a shared memory between them.

**Download:** `Dex_0.1.0_x64_en-US.msi` below. Windows 10 1809+ or Windows 11, with Claude Code and Git for Windows installed. The installer is not code-signed yet — SmartScreen will say *Windows protected your PC*; click **More info → Run anyway**.

## What's in it

**Workspaces and panes.** Named, coloured, persistent workspaces, each a tree of split panes with five layout presets. Every pane is a real shell on a real ConPTY. Workspaces, panes and layouts survive a restart.

**Agents, watched.** Run `claude` in any pane and Dex knows: a status dot on the pane header (running, waiting on you, idle, error, dead), counts in the title bar, and a Windows toast when an agent in a pane you're not looking at stops or needs input — click it to jump there. A live activity pane shows everything every agent has said and done.

**Shared context.** One store per workspace that agents read and write through eight MCP tools: append-only notes, versioned facts under keys, and directed messages. Every agent gets a short digest of what its siblings have done at the start of its turns — nothing when nothing changed. Mirrored as Markdown under `<workspace>/.dex/` so you can read it too.

**Spawning.** An agent can start another on a task, in its own pane and its own git worktree on a new branch, and the child begins work unattended — it even answers Claude Code's folder-trust dialog by itself, only in a worktree Dex created. Depth 2, six live agents per workspace, enforced by Dex rather than by prose. The `dex-agentic` skill teaches agents when spawning is worth it and how to write a brief.

**Repositories and worktrees.** Register repos, get worktrees under `~/dex/worktrees/<repo>/<branch>`, see the branch and change counts. A **diff pane** follows a repository's uncommitted changes, unstaged or staged; a **markdown pane** renders a file as it's written.

**A CLI for everything.** `dex` does what the UI does, and it's what agents use: workspaces, panes (including typing into them), agents, repos, worktrees, context, and the three installers. `--json` on every command.

**Command palette** (`Ctrl+Shift+P`) with fuzzy search over workspaces, panes and commands; `w:` and `p:` to narrow. Every shortcut rebindable in `%APPDATA%\Dex\config.toml`, which hot-reloads and never refuses to start on a bad value — it uses the default and tells you.

**Setup in three clicks.** On first start a panel runs `dex doctor` and offers a button for each thing Dex can set up itself: hooks, the MCP server, the skill. Same commands as the CLI, run in your session.

## How it hooks into Claude Code

Ten hooks (`dex event <kind>`) in your user-level Claude Code settings, ~10 ms each, inert outside a Dex pane; and an MCP server registered at user scope that offers eight tools inside a Dex pane and none elsewhere. Neither is installed by the MSI — you press the buttons, and `dex hooks uninstall` / `dex mcp uninstall` / `dex skill uninstall` take them out again. Your other hooks are never touched, and the first install keeps a backup of your settings file.

## Known limitations

- **Windows only**, by design. Agents running inside WSL are not supported in this release, though the pane model is ready for it.
- **Scrollback does not survive a restart.** Workspaces and layouts do; the terminals start fresh.
- **Diff and markdown panes poll** (every 3 s and 2 s) rather than watching the filesystem.
- **Unsigned installer**, as above.
- Tested against **Claude Code 2.1.273**. The hook and MCP interfaces are Claude Code's public ones; the trust-dialog answer depends on that dialog's layout and is verified per version.

## Verification

213 Rust tests, 111 frontend tests, and a clean-machine run of the installer through to four working agents. The behaviours that would fail silently — PTY survival across workspace switches, an empty digest costing zero bytes, subagent hooks leaving status alone, out-of-order status events resolving to the newest — each have a regression test.
