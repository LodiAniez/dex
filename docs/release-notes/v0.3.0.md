# Dex 0.3.0

The office comes alive, an agent without Claude Code is no longer an agent, and the Cards view is gone.

**Download:** `Dex_0.3.0_x64_en-US.msi` below. Windows 10 1809+ or Windows 11, with Claude Code and Git for Windows installed. Not code-signed yet — SmartScreen will say *Windows protected your PC*; click **More info → Run anyway**. Installing over an earlier version upgrades it; your workspaces, hooks and settings are kept.

## Removed

**The Cards view.** There are two views now, **Terminal** and **Office**, switched from the title bar or with *Terminal view*, *Office view* and *Next view* in the palette. Everything that existed only for the cards went with them — including reading every agent's terminal once a second to draw them; the office now reads a screen only while that agent's panel is open.

Coming from 0.2.0:

- A window that remembered Cards opens as your config says (Terminal unless you set otherwise).
- `view = "cards"` in `config.toml` gives you Office, and `dex config show` says why: *the cards view was removed*. Change it to `"terminal"` or `"office"` when convenient.
- A `[keys]` binding for `view-cards` is reported as something Dex cannot do. The Announce button that sat beside the workspace name in Cards is gone; the loudspeaker on the office floor does the same thing.

## New

### Idle agents do not just sit there

An agent whose task is done gets up to something, a few seconds after going idle: a coffee in the break room (wherever there is room to stand — never on top of a colleague), a go kart up the corridor or round the block, either way round, skipping rope, a body roll or a tumble outside its cubicle, a nap on a camp bed, or a song at its desk. One thing after another, never the same twice running, and two idle agents do different things.

**Give it work and it stops, walks back to its own desk like a normal person, and only then is shown working.** The same if a colleague is on the way over with a message — and the colleague waits until it is back. A kart driver called back at the far side of the block finishes the lap first. An agent that ends while it is out walks to the exit from where it was. With Windows set to reduce motion, nobody gets up.

### The lead shouts for staff

When an agent spawns others — you ask the lead for three engineers — it cups its hands at its desk and shouts to HR: **I NEED 3 ENGINEERS ON THE FLOOR ASAP!** A lead spawns one at a time, so the number grows, and is shouted afresh, as it sends for more: 1 engineer, 2 engineers, 3. Each hire waits a moment inside HR's door so the shout comes first, and one already walking is never sent back by the next shout. Hire from HR yourself and nobody shouts.

### The Activity box minimizes

Bottom left of the floor. Minimized, it is a button in the same corner that counts what has happened since; it stays minimized across restarts until you open it. It also sits below the break room now, not over it.

## Changed

### An agent whose pane no longer runs Claude Code is dead

Claude Code quit with Ctrl+C, crashed, or killed from Task Manager says nothing on its way out, and the agent used to sit "idle" over a bare shell — in the list, at a desk, counted against `agents.max_concurrent` — until someone tried to prompt it. Now, every fifteen seconds, Dex checks that each started agent still has a Claude Code process in its pane, looks again two seconds later to be sure (Claude Code replaces its own process when it updates), and ends the ones that do not.

- The workspace log says why — *kid is dead (Claude Code is no longer running in its pane)* — so a lead learns that its agent crashed rather than waiting on it.
- A pane Dex made for a spawned agent closes with it, as `dex agent stop` closes it. A pane you opened stays, a shell that may say what happened; run `claude` there again and a new agent appears.
- Only on evidence. A pane inside WSL, a process table that cannot be read, or a runtime whose command line cannot be read ends nobody. Claude Code installed through npm, bun or deno is recognised as well as the native build.
- Cost: one read of the process table per sweep, about 0.3 s, and only while a started agent exists.

## Fixed

- Switching workspace in Office view no longer makes the lead there shout for agents it hired long ago.
- A hire already walking in is not sent back to HR's door when the lead shouts again.
- A box found minimized at startup counts what comes after, instead of never counting again.
- Figures fooling around no longer take clicks meant for what is under them.
- The idle loop no longer keeps every timer it has ever set.

## Known limitations

Windows only, no WSL agents yet, scrollback does not survive a restart, diff and markdown panes poll, unsigned installer. A spawned agent whose `claude` never starts is not checked for — it has no session yet, and every hire's first seconds look exactly like that. An agent recalled in the middle of a stretch of walking, rolling or driving finishes that stretch first (under two seconds). The rule about who may stop whom guards against a confused agent; it is not a security boundary. Tested against Claude Code 2.1.274.

## Verification

342 Rust tests and 365 frontend tests, each rule written as a failing test first; every pull request reviewed and its findings fixed before merging. Driven through the real window: all seven antics with their walks out and back, an agent given work mid-roll walking home before typing, three idle agents at once (two drinkers at different places while a kart lapped the block), the shout growing 1 → 2 → 3 as a lead spawned three, no shout on a workspace switch, minimize → count → restart → reopen, agents over bare shells ended within 28 s while one with a live process survived until it was killed, a spawned agent's pane closing with it, and the two fallbacks for anyone who had chosen Cards.
